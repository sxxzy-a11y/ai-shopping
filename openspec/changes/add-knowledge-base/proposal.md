## Why

GPT 方案列的 5 项核心内容里，第 3 项「RAG 商品知识库」是项目**唯一完全空白**的功能——全仓检索 `chroma` / `langchain` / `embedding` / `vector` 零命中。它同时是第 4 项「Agent 多步骤工具调用」的前置：Agent 的四个工具里有三个（商品搜索、预算筛选、多商品比较）项目已经具备，唯一缺的就是「知识库检索」。

现状的能力边界很清楚：系统能算「哪件商品更适合你」，但答不了「主动降噪和被动降噪有什么区别」「带出门的笔记本多重合适」这类**知识型问题**。这类问题不需要商品数据，需要的是选购资料。

## What Changes

- **新增知识语料 `data/knowledge/`**
  - **品类级**：10 个品类各一份选购指南（怎么选、看哪些参数、常见误区）
  - **服务级**：常见问题（术语解释、系统能力与数据限制说明）
  - **商品级**：**不单独写文件**，在构建索引时由现有商品字段合成——避免同一事实写两遍，也就不会出现「改了规格忘了改介绍」的失同步
  - 每份文档带元数据：来源、文档类型、关联商品 ID（商品级）、更新时间

- **新增检索层 `src/knowledge/`**
  - 中文检索用**字符二元组（bigram）索引 + BM25 打分**，纯标准库实现，**零新增依赖**
  - 中文不需要分词器：按字切二元组是 CJK 检索的标准做法，实测有效（见下）
  - 按文档类型加权：问「怎么选」「有什么区别」时，品类级与服务级文档应排在具体商品之前
  - 设相关度阈值：低于阈值判定为「检索不到」，而不是硬返回弱相关结果

- **新增知识问答页**（第 7 个页面）
  - 本地演示模式：直接展示检索到的资料片段与来源，**不做生成**——没把握就不替用户写答案
  - AI 增强模式：把检索到的片段交给模型组织成回答，提示词要求只依据片段，价格必须来自商品数据
  - 两种情况都展示来源与更新时间

- **明确边界：价格与关键参数不走 RAG**
  - 「500 元以内有什么」这类问题必须查结构化商品数据，RAG 只负责语义知识
  - 问答页对涉及价格的问题给出引导，而不是用检索结果拼一个价格出来

- **不做的**：不引入 Chroma、LangChain、embedding 接口或任何新依赖；不做文档自动抓取；不做多轮对话记忆；不改动现有评分与排序逻辑。

## 已实测验证（决定了检索方案）

用 112 条商品字段合成的商品文档 + 3 份示例知识文档（共 115 条）跑了 bigram + BM25 原型：

| 查询 | 检索结果 | 判定 |
|---|---|---|
| 主动降噪和被动降噪有什么区别 | `faq:anc` 61.68，第二名 22.31 | ✅ 正确且优势明显 |
| 笔记本多重适合带出门 | `category:laptop` 10.32 排第一 | ✅ |
| 编程用什么电脑 | `category:laptop` 排第一 | ✅ |
| 今天天气怎么样 | **无任何结果** | ✅ 语料外问题自然拒绝 |

同时也暴露了两个必须在设计里解决的问题：

1. **「通勤戴的耳机怎么选」把某款具体商品排在了选购指南之前**——说明文档类型必须加权，否则通用问题会答成具体商品推荐。
2. **「500 元以内降噪耳机」返回了 2499 元的商品**——证明 RAG 不能用于价格类问题，价格必须走结构化查询。这不是缺陷而是边界，但要在界面与规格里写死。

## Capabilities

### New Capabilities

- `knowledge-base`: 知识语料的组织与元数据、中文检索与相关度判定、引用来源展示、知识问答的两种回答模式、价格类问题不走检索的边界约束。

### Modified Capabilities

- `web-ui`: 「页面构成」需求由五个页面扩展为**七个**——新增知识问答页，并**补上规格中历史遗漏的个人设置页**（实际应用一直是六页，规格只写了五页）；该需求下的既有场景需同步更新。

## Impact

**新增文件**

| 路径 | 内容 |
|---|---|
| `data/knowledge/category/*.md` | 10 份品类选购指南 |
| `data/knowledge/faq.md` | 常见问题（术语解释、系统能力与数据限制） |

| `src/knowledge/index.py` | 倒排索引与 BM25 打分 |
| `src/knowledge/corpus.py` | 语料加载、元数据解析、商品级文档合成 |

| `src/ui/pages/knowledge.py` | 知识问答页 |

**修改文件**

| 路径 | 改动 |
|---|---|

**依赖**

无新增。仍为 `streamlit` / `pandas` / `pydantic` / `httpx` / `pytest` 五个。

**测试**

- `tests/test_knowledge_tokenize.py`、`test_knowledge_index.py`、`test_knowledge_search.py`
- 检索质量基线：用实测过的查询集断言排序正确性
- 语料外问题断言返回空结果
- `tests/test_app.py` 补新页面渲染

**风险**

- **检索质量无监督标准**：相关度阈值定高了会「明明有资料却说找不到」，定低了会返回噪声。缓解：阈值作为 `config` 常量可调，并用固定查询集（正例 + 语料外反例）建立回归基线——这也是「效果评测」子项目的雏形。
- **商品级文档合成后可能触发一致性校验**：`harden-ai-enhancement` 变更设计的矛盾检测会扫描商品文本，合成的文档若包含数值需确认不误报。
- **两份变更的先后关系**：`harden-ai-enhancement` 与本变更互不依赖，可任意顺序实施；但两者都会改动 `src/ai_enhance.py`，同时开工容易冲突，建议串行。

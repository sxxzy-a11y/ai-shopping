**实施中撞到并修掉的两个真问题**（都记在代码注释里）：

1. **索引建在补列之前**，老库直接以 `no such column: user_id` 升级失败。
   建表脚本先于 `_migrate` 执行，而 `CREATE TABLE IF NOT EXISTS` 对老表是空操作——
   紧跟其后的 `CREATE INDEX ... (user_id, ...)` 必然撞墙。索引已移进 `_migrate`。
2. **DDL 不自动开事务**：Python 的 `sqlite3` 只在 DML 前隐式开事务，
   `ALTER TABLE` / `CREATE INDEX` 各自自动提交。原来的写法看起来是
   「一个事务」，实际中途失败时表已经被改掉了，而 `rollback()` 无事可回滚。
   已显式 `BEGIN`。「迁移中途失败」那条用例就是逮它的——只断言「抛了异常」
   根本区分不出这种半迁移状态。

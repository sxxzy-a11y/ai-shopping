## Context

「AI 问答」页的前身是 `add-knowledge-base` 变更交付的「知识问答」页，其形态是「本地展示原文 + AI 可选增强」。本次按使用反馈调整定位：**这是一问一答的问答页，回答由 AI 组织，资料只在内部作为依据。**

现有约束与既有机制：

| 来源 | 约束 |
|---|---|
| `openspec/project.md` 第 3 条 | 离线可用是硬约束——**本变更在该页上做出例外，理由见 proposal** |
| `knowledge-base` 规格 | 回答只能依据检索片段；片段不足要说明；不得编造来源 |
| `ai-enhancement` 规格 | 模型输出是**不可信输入**，必须后验校验（价格、排他性结论），失败丢弃 |
| `harden-ai-enhancement` 已落地 | `_sanitise_why` 检查链、`find_unsupported_claims`、`data_issues` 属性级拦截 |
| 检索实现 | BM25 + 文档类型加权（商品 0.45）+ 品类加权 1.6 + 绝对阈值 3.0 |

## Goals / Non-Goals

**Goals:**

1. 页面成为「问 → 得到回答」的一步式体验，AI 恒开
2. 检索精度提升：喂给模型的片段少而准
3. 未配置密钥 / 调用失败时，给出**可行动**的提示，不静默、不半成品
4. 保留价格类问题的引导边界
5. 既有测试全绿；评测集结果不回归

**Non-Goals:**

- 不做多轮对话、不做追问改写（与 `add-knowledge-base` 的 Non-Goals 一致）
- 不引入向量检索或新依赖
- 不改检索算法本身（仍是 bigram + BM25），只收紧**结果取舍**
- 不把「找到的资料」另找一个角落藏起来——按需求就是不展示

## Decisions

### D1. 页面更名「AI 问答」，键与函数名保持不变

**选择**：用户可见文案全部改为「AI 问答」（导航、页头）；`NAV_ITEMS` 中的页面键、`src/ui/pages/knowledge.py` 文件名、`zg_knowledge_*` 会话键**保持不变**。

**理由**：改名是**文案层**的调整。把文件名和会话键一起改，会牵连 `state.py`、测试与历史会话状态，收益是零；而页面名是用户唯一会看到的东西。

### D2. 恒开 AI，但保留三层形态

**选择**：移除该页的开关；渲染时按配置与结果分三种形态：

| 形态 | 条件 | 界面 |
|---|---|---|
| 作答 | 已配密钥且调用成功 | 只展示回答 |
| 未配置 | 没有密钥 | 提示「本页需要 AI：在 `.env` 配置 `ZHIGOU_LLM_API_KEY` 后重启」，并给「去智能分析按条件筛选」的入口 |
| 失败 | 调用抛领域异常 | 提示失败原因 + 建议重试；不展示任何半成品 |

**理由**：需求是「AI 一直保持增强」，所以不设开关；但「没配密钥」与「调用失败」是两种不同的事，提示必须区分——前者用户能自己去配置，后者只能重试。

**放弃了什么**：该页的离线可用性（见 proposal 的冲突说明）。分析、比较、历史、设置四页不受影响。

### D3. 检索精度：相对截断 + 条数上限

**选择**：新增 `KNOWLEDGE_RELATIVE_CUT`（初值 0.35）；结果保留条件为 `score >= max(KNOWLEDGE_MIN_SCORE, top_score × 系数)`；`KNOWLEDGE_MAX_RESULTS` 5 → **3**。

**实测依据**（当前 23 条语料）：

| 查询 | 原前 5 分 | 取 0.35 后保留 |
|---|---|---|
| 处理器档位是什么意思 | 8.57 / 4.13 / 2.41 / 1.35 / 1.34 | 2 条（8.57、4.13） |
| 编程用什么电脑 | 6.68 / 2.82 / 1.86 / 1.80 / 1.80 | 2 条 |
| 笔记本多重适合带出门 | 7.57 / 2.73 / 1.17 / 1.15 / 1.14 | 2 条 |
| 系统匹配评分是怎么算出来的 | 19.20 / 1.26 / 1.09 / 0.94 | 1 条 |
| 苹果 iPhone 16 怎么样 | 4.35 / 2.09 / 2.00 / 1.30 / 1.09 | 3 条（上限） |

**理由**：绝对阈值 3.0 只能保证「有没有」，不能保证「准不准」——大量 1.x–2.x 的弱命中会穿过绝对阈值被喂给模型。相对截断按「与第一名同一量级」取舍，比调绝对阈值更符合意图；条数上限 3 进一步限制噪声。

**取舍**：并列相关的第二篇资料若分差超过 0.35 倍会被丢掉（如术语题只留 FAQ，丢掉品类指南）。用固定查询集回归确认「该保留的仍然保留」；系数放 `config` 可调。

### D4. 不再展示片段：以提示词与校验兜底

**选择**：页面删除「找到的资料」区与来源引用；模型仍收到片段（`answer_from_knowledge` 不变），并沿用既有强制校验（价格必须来自片段、排他性结论一律拒绝）。

**理由**：需求明确不展示。撤掉来源展示后，「回答有依据」由**机制**而不是**展示**保证——这依赖 `harden-ai-enhancement` 已落地的检查链，本变更不新增防线、只复用。

**放弃了什么**：用户自行核对答案的能力。这是明确的产品取舍，规格里写明。

### D5. 规格层面撤销「引用来源展示」需求

**选择**：在 `knowledge-base` delta 中以 REMOVED 撤销该需求，而不是留着一个「不展示来源」的废需求。

**理由**：需求描述的是界面行为，界面不再有来源区，需求即失效。留着会诱导后来者「补上来源展示」——那是被明确否掉的方向。

### D6. 片段抽取放宽为「按重合度取前几段」

**选择**：`extract_excerpt` 不再要求所选段落与命中段相邻，直接按与查询的字面重合度取前 `EXCERPT_MAX_PARAGRAPHS` 段；`EXCERPT_MAX_CHARS` 420 → 600。

**理由**：实测复现了问题——问「笔记本多重适合带出门」，第一名的《笔记本电脑选购指南》里明明有「1.2–1.4kg 属于便携」这一行，但抽取只给了「命中段 + 相邻段」（性能与重量的矛盾），模型据此只能回答「资料没有覆盖具体重量」。片段**不再直接展示**之后，行文连贯不再是目标，**覆盖关键信息**才是。

**放弃了什么**：拼接出的片段读起来更跳跃。既然不再展示给用户，这个代价没有实际影响。

### D7. 品牌加权：宽问题（只问品牌）也必须有结果

**选择**：新增 `KNOWLEDGE_BRAND_BOOST`（3.0）。查询点名了语料中的品牌时，该品牌的商品条目得分 ×3；点名了品类时品牌加权有**品类约束**（「华为笔记本」不给华为手机加权）。

**实测依据**（不加权 → 加权后）：

| 查询 | 不加权 | 加权后 |
|---|---|---|
| 华为怎么样 | 0 条（最高 1.91 < 阈值 3.0） | 3 条华为商品 |
| 红米怎么样 | 0 条 | 2 条红米商品 |
| 华为笔记本怎么样 | 2 条 | 华为两台笔记本置顶，华为手机被品类约束排除 |
| 戴森吸尘器怎么样 | 0 条 | 0 条（品牌不在语料中，不误伤） |

**理由**：品牌词只有两三个字，BM25 得分天然低；用户问「华为怎么样」问到了点子上，被阈值挡成「检索不到」是检索侧的失败，不是用户的问题。与既有的品类加权（`KNOWLEDGE_CATEGORY_BOOST`）完全对称。

### D8. 回答口径：直接回答，不谈「资料」

**选择**：改写作答系统提示词——直接回答问题本身，禁止出现「资料」「片段」「知识库」「没有覆盖」等元话语；问得宽就把该品牌/品类的要点综合起来讲；只有片段完全无法回答时才用一句话说明。

**理由**：用户要的是答案，不是检索过程的旁白。此前「现有资料没有覆盖这一点」的句式把系统的内部状态推给了用户。诚实性不靠这句免责声明保证，靠的是机制：片段是唯一依据 + 价格校验 + 排他性结论拦截。

## Risks / Trade-offs

**[相对截断漏掉并列资料]** → 系数取通过值里最宽松的一档；固定查询集（正例 + 语料外反例）回归守住。

**[未配密钥时页面空转]** → 提示必须可行动（写清环境变量名与重启步骤），并提供去「智能分析」的入口。

**[删掉来源后幻觉风险上升]** → 依赖既有两条强制校验（价格来自片段、排他性结论拒绝）+ 提示词「只依据片段，不足则说明」。这些均已落地且有测试。

**[品牌加权可能引入品牌内噪声]**（问「华为笔记本」时华为手机也过线）→ 已加品类约束（点名品类时不跨品类加权），并有专项测试守护。

**[评测集与用例引用了旧的「知识问答」文案]** → 归档前跑评测集与全量测试，凡引用旧文案处一并更新。

## Migration Plan

1. `config`：加相对截断系数、条数上限改 3
2. `search.py`：实现相对截断；跑固定查询集确认
3. 页面：改名、去开关、去片段区、三形态提示
4. `app.py` 导航更名
5. 测试适配与新增（截断行为、无开关、无片段区、无密钥提示）
6. 文档同步（README / docs / demo_script）
7. 归档（合并 delta 进 `openspec/specs/`）

**回滚**：纯界面与参数调整，不涉及数据与业务链路；恢复片段区与开关即可回到旧形态。

# 设计

## 决策

### D1. 文档仍以文件为唯一事实来源

新增写到 `data/knowledge/custom/<slug>.md`，删除即删文件。不引入数据库表存文档：
语料需要可 diff、可回滚、可手工编辑，文件是最合适的载体；数据库只存**派生**的向量。

### D2. 只允许删除文件型资料

商品级文档由商品字段合成（`synthesize_product_document`），没有独立文件，删除它等于
删商品——那不是知识库的职责。UI 上标注「自动生成」，删除入口只对品类级/服务级出现。

### D3. 同分类只允许一份指南

`doc_id` 由 `type:category` 派生；同分类两份指南会产生重复 `doc_id`，检索与切片都会
出现难以解释的重复。新增时若该分类已有品类级文档，直接拒绝并提示。

### D4. 文件名自动去重

标题 → slug（保留中文与字母数字，其他字符折叠为 `-`）；已存在则追加 `-2`、`-3`。
文件名只影响可读性，文档 ID 由 front-matter 决定。

### D5. 二次确认

删除按钮旁要求勾选「确认删除」；避免误点造成语料丢失（文件不在 git 里也能恢复，
但恢复成本高）。

## 风险

- 新增文档正文质量由管理员负责；索引完成后才会被检索到（关键词立即可用，向量需重建）。
- 删除品类指南后，该分类的知识问答会变弱——界面提示「该分类仍有商品级资料」。

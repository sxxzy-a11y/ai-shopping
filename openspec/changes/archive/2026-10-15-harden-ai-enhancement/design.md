## Context

本项目的抗幻觉设计有一条明确主线：**结构化数据由数据库提供，模型不能编造**。目前这条主线只落地了一个后验检查——`src/ai_enhance.find_invented_prices()`，校验 AI 解读中出现的价格能否在传入数据中找到对应值，对不上就丢弃整条解读。

这条主线还有两个缺口（README §13.3 场景 5 与场景 6），以及一处已登记的真实隐患（README 附录 C：内置默认端点指向 `api.openai.com`，与 `.env.example` 的 DeepSeek 不一致）。

现有相关约束：

| 位置 | 约束 |
|---|---|
| `ai-enhancement` 规格 | 「AI 输出不得编造事实」——但只提到「价格与参数均可在传入数据中找到」，参数部分没有实现 |
| `product-catalog` 规格 | 已有「缺失核心参数的商品须标记信息不完整」——处理**字段缺失**，未处理**字段矛盾** |
| `src/ai_enhance.py` 模块 docstring | 三条硬规则：模型输出当不可信输入、不许编造事实、失败就降级 |
| 项目设计基线 D3 | 加载层容错优先于严格校验，单条失败只降级该条，不整批失败 |
| 项目设计基线 D8 | 异常统一走 `errors.py` 的中文映射 |

## Goals / Non-Goals

**Goals:**

1. 商品记录的内部矛盾能被识别，且**不污染输出**——存疑商品照常参与流程，只是被矛盾的属性不作为事实陈述
2. AI 解读的断言校验从「只查价格」扩展为「查价格 + 查参数数值 + 查排他性结论」
3. 默认 LLM 端点与 `.env.example` 对齐，并用测试锁死
4. 补全 `ai-enhancement` 规格的 Purpose（当前为归档占位符 TBD）

**Non-Goals:**

- 不做通用的一致性推理，只做**高精度、可枚举**的规则
- 不引入 RAG、Agent，不改评分与排序逻辑
- 不修改商品数据内容来「通过」校验
- 不补其余 7 份规格的 Purpose（另行处理）
- 不做属性级置信度打分或多来源交叉验证

## Decisions

### D1. 一致性检测放在独立模块 `src/consistency.py`，不塞进 `data_loader`

**选择**：新增 `src/consistency.py`，暴露 `check_product(product) -> list[Issue]`。`data_loader` 在逐条加载时调用它，把结果挂到 `Product.data_issues`。

**理由**：`data_loader.py` 已有 317 行、职责是「加载与逐条容错」；把规则引擎混进去会让两件事的变更频率耦合。项目设计基线 D2 就是「按职责切分模块」，规则集未来会增长，独立成模块便于单独测试。

**放弃了什么**：多一个模块的间接层，加载路径多一次函数调用（可忽略）。

**备选**：直接写进 `data_loader`——被否，见上。运行时按需检测——被否，商品卡片、比较页、导出报告、AI 提示词四处都要用，每次重算不划算，且无法在加载阶段做整体校验。

**注意**：检测结果**不参与评分**。存疑是数据质量问题，不是商品劣势——把它算进分数等于把数据缺陷转嫁成商品缺点，会让用户看到错误的推荐理由。

### D2. 规则集只保留高精度规则，且「现有数据集误报为 0」是硬验收线

对现有 112 条商品实测了候选规则，结果决定了这个设计：

| 候选规则 | 命中 | 判定 |
|---|---:|---|
| `pros` 称「轻便」但 `weight_kg >= 2.0` | 2 | ❌ 误报——婴儿车 6.8kg 确实算轻 |
| `cons` 含「重」但重量很小 | 1 | ❌ 误报——原文是「承**重**上限偏低」 |
| `has_dedicated_gpu: false` 但文本提「独显」 | 5 | ❌ 误报——原文是「**无**独显」 |
| `foldable: false` 但文本提「折叠」 | 4 | ❌ 误报——原文是「**不可**折叠」 |

**入选规则（现有数据命中为 0）**：

| # | 规则 | 类型 |
|---|---|---|
| R1 | tier 类字段取值越界（不在 1–5） | 结构化 |
| R2 | 价格缺失或非正 | 结构化 |
| R3 | `pros` 与 `cons` 存在完全相同条目 | 结构化 |
| R4 | `specs` / `use_cases` / `pros` / `cons` 为空 | 结构化 |
| R5 | `has_dedicated_gpu: false` 且文本**肯定式**提独显 | 结构化对照 + 文本 |
| R6 | `foldable: false` 且文本**肯定式**提折叠 | 结构化对照 + 文本 |

**理由**：一条不准的规则会让正常商品被污名化，**比不做更糟**。宁可规则少、覆盖窄，也不能误报。

**放弃了什么**：放弃了「检测所有可能的矛盾」这个目标。像「轻便 vs 重」这种依赖品类常识的判断不在范围内。

### D3. 文本规则必须否定感知 + 单位感知

**选择**：文本匹配前先判断关键词是否被否定——关键词前 3 个字符内出现 `无不非没未缺乏缺少没有不支持不含` 任一字符，则视为否定式，**不构成矛盾**。

**实测验证**（这是 D3 的核心依据）：

```
规则 R5（false + 肯定式提独显）  误报：0 条
规则 R6（false + 肯定式提折叠）  误报：0 条    ← 加了否定感知后从 4 条降到 0
```

反向核对确认匹配器不是空转：5 台带独显的笔记本中，有 4 台的文本**肯定式**提到了「独显」，说明匹配器确实能识别肯定式提及，只是因字段值为 `true` 而不触发标记。

**单位感知**：`weight_g`（手机/耳机/键盘/服饰/运动，63 条）与 `weight_kg`（笔记本/家具/母婴，33 条）并存，语义随品类变化。数值比较前必须先归一化单位，且**只在同一品类内比较**。

**放弃了什么**：基于语义理解的矛盾判断（如「轻便」的语境依赖性）。当前手段达不到高精度，做不如不做。

### D4. 断言校验扩展在 `_sanitise_why` 的检查链上，不新建流程

**选择**：把现有的 `_sanitise_why` 从「查价格」扩展成一条检查链：价格 → 参数数值 → 排他性结论。任一检查失败即返回 `None`，调用方丢弃该条（**沿用现有语义**）。

**理由**：现有的「校验失败丢弃该条、保留规则结果」策略已经过真实联调验证，行为正确且有测试覆盖。扩展检查项比新建一套流程风险低得多。总述（`overview`）走同样的检查链。

**放弃了什么**：没有做「部分修正」（比如把错误数值改对再展示）。改写模型输出会引入新的不可控因素，丢弃更安全。

### D5. 参数数值校验只在「数字 + 明确单位」时触发

**选择**：只有形如 `1.28 千克`、`10 小时`、`16GB` 的**带单位数值**才进入校验；裸数字不检查。

**理由**：裸数字里混着序号（「第 1 名」）、年份、评分（「81.9 分」），一旦纳入校验会大量误杀。带单位的数值歧义小得多。

**放弃了什么**：覆盖面。模型若用裸数字断言参数（「内存 16」），校验抓不到——接受这个漏放。

### D6. 排他性结论用固定模式表，不用通用形容词分析

**选择**：维护一张绝对化表述模式表（`同类最强`、`销量第一`、`口碑最好`、`全网最低`、`遥遥领先` 等），命中即判定无依据。

**理由**：这类结论的共同特征是「断言了数据里根本不存在的比较维度」——数据集中没有销量、口碑、排名数据。用模式表可以精确命中，且**零误杀**（正常解读不会这么说）。

**放弃了什么**：模式表之外的变体抓不到。宁可漏放。

### D7. 存疑标记如何影响 AI 解读

**选择**：`Product.data_issues` 携带**被矛盾的属性键**与原因，随 `_product_brief` 一并传给模型（提示词明确「该商品以下方面资料存疑，不要就其下结论」）；输出侧，若解读断言了该商品被标记的属性，该条被丢弃。

**理由**：这是规格里「仅其被矛盾的具体属性不得作为事实输出」的落点——只拦被标记的那一个属性，不牵连整件商品。因为高精度规则命中极少（当前 0 条），运行时开销可忽略。

**放弃了什么**：只做提示词软约束（不可靠，README 已把这种状态标为 🚧）；也只做整体丢弃（会牵连商品其他正常属性）。

### D8. 默认端点对齐 = 改常量 + 解析 `.env.example` 的一致性测试

**选择**：`DEFAULT_LLM_BASE_URL` / `DEFAULT_LLM_MODEL` 改为与 `.env.example` 登记值一致；新增测试**读取 `.env.example` 文本**、解析出对应键值，断言与 `config` 中的常量相等。

**理由**：单纯改常量只解决当下，不改测试就还会再次漂移。测试读 `.env.example` 而非硬编码期望值，才能让两者真正绑定。

**放弃了什么**：没有在运行时校验二者一致（启动即失败过于激进，且不影响本地演示模式运行）。

### D9. 补全 Purpose 直接编辑 `openspec/specs/ai-enhancement/spec.md`

**选择**：Purpose 不属于需求，delta 机制（ADDED/MODIFIED Requirements）覆盖不到，因此作为对本文件的直接编辑，在 `tasks.md` 中单独列一条任务。

**理由**：归档时 delta 只合并需求块，Purpose 保持 `TBD` 会一直留在规格库里。

## Risks / Trade-offs

**[断言校验误杀有依据的解读]** → 现有价格校验踩过这个坑：模型说「这三件都在 4000 元预算内」，曾被误判为编造价格，因此 `allowed_prices` 特意并入了用户预算。新增检查沿用同一条教训——参数数值校验把**候选商品的全部字段值**与**用户预算**都纳入允许集；排他性结论用固定模式表，不做模糊判断。宁可漏放，不可误杀。

**[存疑标记污名化正常商品]** → 以「现有 112 条数据误报为 0」作为硬验收线，且规则集只保留经实测验证的高精度规则。标记文案用「资料存疑」而非「数据错误」，表明是提示核实而非判定有错。

**[规则集增长后误报回归]** → 每条规则必须有配套的夹具测试（构造的矛盾记录必须命中）与全量数据回归测试（现有数据必须零命中）。两条断言同时存在，才能防止「为了通过某条规则而放宽另一条」。

**[存疑标记影响评分]** → 明确设计为不参与评分（D1），并在测试中断言存疑商品的分数与未标记时一致。

**[单位归一化引入新错误]** → 单位转换只在同品类内做数值比较时使用，不写回数据、不改变展示值，影响面限制在检测内部。

**[改默认端点影响既有部署]** → 只有「未配置任何环境变量」时才会走到默认值。已配置 `.env` 的部署完全不受影响。当前 `.env` 已配置真实 Key，因此本次改动对现有运行环境是零影响。

## Migration Plan

1. 改 `src/config.py` 两个常量 + 加一致性测试——**风险最低、可独立验证**，先做
2. 新增 `src/consistency.py` 与规则集，接入 `data_loader`——先只算不用，跑全量数据确认零误报
3. 界面与报告展示存疑标记
4. 扩展 `_sanitise_why` 的检查链——先参数数值、后排他性结论，各自独立测试
5. 把 `data_issues` 接入 AI 提示词与输出侧属性级拦截
6. 补全规格 Purpose、同步 README 与 docs

**回滚**：每一步都是独立可回退的增量。一致性检测可通过让 `data_loader` 不调用检测函数恢复到原状；断言校验的每一步是检查链上独立的一环，去掉即回到当前行为。

## Open Questions

1. **存疑标记的展示强度**——是角标提示，还是在商品卡片上占一行说明？规则命中为 0 时用户看不到任何差异，因此这一项可以等真有命中数据时再定。
2. **规则集是否需要可配置**——当前 6 条规则硬编码在模块里。若后续品类继续扩展、规则增长到十余条，可能需要像 `SCORING_WEIGHTS` 那样集中到 `config.py`。本次先不抽象，避免过早设计。
3. **是否需要「数据体检」CLI**——把全量一致性检查作为 `scripts/` 下的一个命令暴露出来，便于接入真实数据时先跑一遍。本次不做，但规则模块的接口（`check_product` 纯函数）已经为它留好了位置。

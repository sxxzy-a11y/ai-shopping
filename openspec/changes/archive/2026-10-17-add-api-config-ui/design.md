## Context

配置目前只从环境变量读取（`config.llm_*` / `config.embedding_*`）。测试靠 conftest 删密钥隔离；运维靠改 `.env` + 重启。用户希望能在界面里切换配置。

约束：

| 来源 | 约束 |
|---|---|
| `ai-enhancement` 规格 | 密钥只从环境变量读；不写日志/导出/界面回显 |
| 安全基线 | 密钥不出现在明文、日志、导出文件；界面只显示脱敏片段 |
| 现有服务单例 | `ai_service.get_service()`、`embeddings.get_service()` 进程内缓存 |
| 测试隔离 | conftest 把设置/数据库指到 tmp，并删除环境密钥 |

## Goals / Non-Goals

**Goals:**

1. 管理员在「项目说明」页即可改两套 API 配置并测试
2. 保存后立即生效，不需要重启
3. 普通用户只能看状态，不能改
4. 密钥始终不明文回显、不进日志
5. 测试仍然完全离线、不读开发机真实密钥

**Non-Goals:**

- 不做多配置档案（profile）切换
- 不做密钥加密存储（本机演示级；加密密钥仍需落地，收益有限）
- 不改任何业务调用方式（仍走 `ai_service` / `embeddings`）

## Decisions

### D1. 覆盖文件而非运行时内存配置

**选择**：`storage/api_config.json` 存界面填写的项，`config.*()` 读取顺序为 **文件 > 环境变量 > 默认值**；文件不存在或某项为空时回退。

**理由**：只存内存配置的话，重启即失效，用户还得回到 `.env`；写进 `.env` 则需要解析/回写用户文件，风险更高（注释、格式、编码都可能被破坏）。独立 JSON 文件互不干扰，删除即恢复环境变量配置。

**放弃了什么**：配置分散在两处（文件 + env）。用界面上的「恢复为环境变量配置」消除歧义，并在页面标明当前值来自哪里。

### D2. 只允许白名单字段，空值不写入

**选择**：`api_config.py` 只接受 7 个键（llm_api_key/base_url/model、embedding_api_key/base_url/model/dim）；保存时**跳过空字符串**，另有显式「清除全部覆盖」操作。

**理由**：空值语义必须是「不修改」。否则用户只想换模型名时，密钥输入框留空会把密钥清掉。

### D3. 保存后重置单例并刷新页面

**选择**：`ai_service.get_service()` **本来就是每次新建**（无单例），无需重置；`embeddings.reset_service()` 用于清掉缓存的 Embedding 单例。保存成功后调用并 `st.rerun()`。

**理由**：真正会缓存旧配置的只有 Embedding 服务；不重置的话「保存成功但向量请求还打旧地址」。

### D4. 测试按钮复用现有 probe

**选择**：对话模型复用 `ai_service.probe()`；向量化发一段 `"测试"` 文本并校验维度。

**理由**：避免为「测试连接」造第二套请求逻辑。

### D5. 界面只对管理员开放编辑

**选择**：状态信息所有登录用户可见；输入框与保存按钮仅管理员可见（页面入口有 `require_admin` 的同类守卫）。

**理由**：密钥是全局配置，普通用户改它等于改所有人的服务。

## Risks / Trade-offs

**[本机文件存明文密钥]** → 明确写入文档：这是演示级方案；文件在 `.gitignore`、界面不回显、日志脱敏；需要更强安全时用环境变量并删除文件。
**[保存后旧单例仍被引用]** → 页面保存即重置；测试覆盖「保存后 get_service 返回新配置」。
**[测试读到真实文件]** → conftest 强制把 `ZHIGOU_API_CONFIG_PATH` 指到 tmp，并断言测试期间未配置。
**[维度填错]** → 保存前校验正整数；测试连接时校验返回维度，不匹配给出明确提示。

## Why

README（目标态蓝图）在 §13.3 列出 6 个抗幻觉场景，其中**场景 5「商品资料中出现互相矛盾的描述」完全没有机制**，**场景 6「用户要求模型提供没有数据依据的性能结论」只靠提示词约束、无强制校验**；同时附录 C 记录了一处真实隐患：`src/config.py` 的内置默认端点是 `api.openai.com`，与 `.env.example` 登记的 DeepSeek 不一致，漏配环境变量时会静默打向错误服务商。

三者属于同一条主线——**系统必须拒绝断言没有依据的东西**。当前的抗幻觉防线只有「价格交叉校验」一种后验检查（`find_invented_prices`），本次把它扩展成通用的断言校验，并补上数据侧的一致性识别。

## What Changes

- **新增：商品记录内部矛盾的识别与存疑标记**
  - 检测商品记录中结构化字段与文字描述之间的内在矛盾
  - 命中记录标记为「资料存疑」，在商品卡片、比较页与导出报告中明示
  - 存疑商品**仍参与筛选与评分**（不清除，避免"删数据解决校验"），但其被矛盾的属性不得作为事实输出
  - **检测规则必须是高精度的**：实测表明朴素关键词匹配会产生系统性误报，详见下方"已实测的误报"

- **新增：无数据依据的性能结论拦截**
  - 把现有的「价格交叉校验」扩展为通用的**断言交叉校验**
  - AI 解读中的数值型参数断言（重量、续航、内存等）必须能在传入数据中找到对应值
  - 无依据的排他性/绝对化结论（「同类最强」「销量第一」）被拦截
  - 拦截后的策略沿用现有做法：**丢弃该条解读、保留规则结果**，不整段失败

- **修改：默认 LLM 端点与服务商配置对齐**
  - `DEFAULT_LLM_BASE_URL` / `DEFAULT_LLM_MODEL` 改为与 `.env.example` 一致
  - 新增测试锁死两者的一致性，防止再次漂移
  - README §2.1 的警告与附录 C 的已知限制可随之移除

- **补全 `ai-enhancement` 规格的 Purpose**（当前仍是归档占位符 `TBD`）

- **不做的**：另外 7 份规格的 Purpose 仍为 TBD，**不在本次范围**（另行处理）；不引入 RAG 或 Agent；不修改评分与排序逻辑；不改动商品数据本身的内容。

## 已实测的误报（决定了检测规则的设计约束）

对现有 112 条商品实测朴素规则，结果证明**直觉上的检测方法不可用**：

| 候选规则 | 命中 | 实际性质 |
|---|---:|---|
| pros 称「轻便」但 `weight_kg >= 2.0` | 2 | **误报**——婴儿车 6.8kg 确实算轻 |
| cons 含「重」但 `weight_kg` 很小 | 1 | **误报**——原文是「承**重**上限偏低」 |
| `has_dedicated_gpu: false` 但文本提「独显」 | 5 | **误报**——原文是「**无**独显」，正确的否定陈述 |
| `foldable: false` 但文本提「折叠」 | 4 | **误报**——原文是「**不可**折叠」 |
| tier 字段越界（不在 1–5） | 0 | ✅ 高精度 |
| 价格缺失或非正 | 0 | ✅ 高精度 |
| pros 与 cons 内容重复 | 0 | ✅ 高精度 |
| `specs` / `use_cases` / `pros` / `cons` 为空 | 0 | ✅ 高精度 |

**结论**：矛盾检测必须做到 (1) 否定感知——「无独显」不是矛盾；(2) 单位与品类感知——`weight_g` 与 `weight_kg` 并存且语义随品类变化；(3) 结构优先——优先用结构化字段互相印证，而非文本关键词。

验收基线：**新规则在现有 112 条数据上误报必须为 0**，正例由测试夹具构造。

## Capabilities

### New Capabilities

无。本次不引入新能力，只在现有能力上收紧约束。

### Modified Capabilities

- `product-catalog`: 新增「商品记录的内部矛盾须被识别并标记为存疑」的需求。该能力已有「缺失核心参数的商品须标记信息不完整」的约定，「字段缺失」与「字段矛盾」是同一类数据质量问题的两面，归属此处。

- `ai-enhancement`: 新增「不得断言无数据依据的结论」需求（覆盖 README 场景 5 的输出侧与场景 6）；修改「模型调用封装」需求，增加「默认端点须与服务商登记配置一致」的场景。

**风险**

- 断言校验过严会误伤正确解读（现有价格校验就踩过这个坑：模型说「都在 4000 元预算内」曾被误判为编造价格，因此 `allowed_prices` 特意并入了用户预算）。新增检查必须同样保守：**宁可漏放，不可误杀**。
- 存疑标记若规则不准，会让正常商品被污名化，比不做更糟。因此以"现有数据误报为 0"作为硬验收线。
- `add-knowledge-base` 变更同样会改动 `src/ai_enhance.py` 与 `src/config.py`（其检索参数与「基于片段回答」功能）。两个变更互不依赖，但需**串行实施**：本变更建议先行（第 1 组任务仅端点对齐，风险最低），且本变更落地的检查链与价格允许集机制，可被该变更的任务 7.2 直接复用。

## 4. 断言交叉校验：参数数值

- [x] 4.1 在 `src/ai_enhance.py` 抽出带单位数值的识别逻辑（数字 + 明确单位），裸数字不纳入。单位表按「单位族 + 换算倍数」组织，`1.28 千克` 与 `1280 克` 归一后可比。
- [x] 4.2 实现 `find_unsupported_spec_claims(text, allowed)` — 允许集**按单位族分组**（`{族: [规范化取值]}`，由 `spec_claim_values()` 生成），因为跨单位比较必须先归一化。**某单位族完全没有数据时不判定**：缺数据不等于编造，宁可漏放。
- [x] 4.3 把该检查接入 `_sanitise_why` 的检查链（价格 → 参数数值），任一失败返回 `None`
- [x] 4.4 总述 `overview` 走同一条检查链
- [x] 4.5 测试：数值与传入数据一致的解读被保留（正例，防误杀）
- [x] 4.6 测试：数值无法对应的解读被丢弃，且不展示给用户
- [x] 4.7 测试：裸数字（序号、评分、年份）不被误判

> **实现中发现并修正的一处设计缺陷**：容差原按「写法精度」取半径（`1.3` → ±0.05），
> 但 `1TB` 写作 0 位小数会得到 ±0.5TB = ±512GB 的容差，正好把数据里的 512GB 包进去——
> 等于放过了「1TB」这种量级级的高报。测试 `32GB 内存加 1TB 固态` 抓到了它。
> 改为**相对容差**（2%，下限 0.05）：四舍五入过得去（1.28→1.3 ✓），量级差异过不去（512GB→1TB ✗）。

## 5. 断言交叉校验：排他性结论

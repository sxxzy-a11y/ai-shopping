# 项目约定（OpenSpec 全局约束）

每个新变更的 proposal 与设计 SHALL 遵守本文件的约定；与本文件冲突的方案需要在 proposal 的 Why 中显式说明并给出理由。

## 项目概况

**智购参谋**（SmartBuy AI Assistant）——面向 AI 创新大赛的可解释消费决策助手。
当前基线：10 份能力规格（52 需求 / 158 场景），696 条测试，Streamlit 单体。

## 技术约束（「够用版」决策，2026-10-15 确立）

1. **保持 Streamlit 单体**。FastAPI + Vue 3 前后端分离与 MySQL 迁移**暂缓，不在任何新变更范围内**；业务逻辑已与界面解耦（`src/` 不依赖 Streamlit），未来如需迁移可原样搬走。
2. **零新增运行时依赖**。运行时依赖固定为 5 个：`streamlit` / `pandas` / `pydantic` / `httpx` / `pytest`。不引入 LangChain、Chroma、Embedding 接口；中文检索用字符二元组 + BM25 纯标准库实现。新增依赖必须在 proposal 中论证为什么标准库与现有依赖无法解决。
3. **离线可用是硬约束**。不配密钥、断网状态下全部功能必须可演示；AI 相关功能一律失败降级到本地模式，降级时明确告知用户，不返回半成品。
4. **架构债不还**。不做账号体系、多用户、支付交易、爬虫、微服务；数据库维持 SQLite。

## 抗幻觉主线（不可违背）

- 结构化事实（价格、参数）只来自商品数据，模型不得编造
- AI 输出是**不可信输入**：所有断言必须经过程序化校验，校验失败丢弃该条、保留规则结果，不整段失败
- 校验规则宁可漏放、不可误杀；数据缺失标注「信息缺失」，不当成最低分
- 演示数据诚实标注（`data_source` / `updated_at`），不得伪装成实时市场数据

## 工程约定

- 规格驱动：行为变更先建 change（proposal + delta specs + tasks），归档时合并进 `openspec/specs/`
- **严格串行**：同时只开一个变更；阶段顺序与五大核心内容的映射见 `docs/roadmap.md`
- 业务规则放 `src/`（不依赖 Streamlit），界面只出现在 `src/ui/`
- 领域异常统一走 `errors.py` 的中文映射；界面不出现堆栈与文件路径
- 每条新行为有配套测试；测试不联网、不需密钥（沿用 `conftest.py` 的隔离夹具）
- 配置常量集中在 `src/config.py`；可调参数（权重、阈值）不写死在业务模块里

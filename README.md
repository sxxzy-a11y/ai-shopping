# 智购参谋

**把一句“预算 2000，主要拍照”变成一份能看懂的购买建议。**

智购参谋是一个面向 3C 选购的 Web 应用。它先把你口语化的需求拆成预算、品类、用途和偏好，再从商品库里筛选、按匹配度打分排序，最后用知识库和受控的 AI 工具补充解释。

它不替用户下单，也不假装自己是实时比价平台。它解决的是买之前的那个问题：**在有限预算里，哪件商品更适合这次的具体用途，为什么。**

- 在线演示：<https://ai-shopping-10.streamlit.app/>
- 代码仓库：<https://github.com/sxxzy-a11y/ai-shopping>
- 技术栈：Python、Streamlit、SQLite、pandas、pydantic、httpx
- 当前数据：20 件商品，2 个品类（笔记本电脑、手机），13 个品牌

> 在线演示部署在 Streamlit Community Cloud。闲置一段时间后应用会休眠，第一次打开可能需要等待几十秒。当前代码默认开放注册；如果部署时关闭了注册，登录页不会显示注册入口。公开演示只用于体验，不要输入真实个人信息。

---

## 1. 为什么做这个

买一台手机或笔记本，通常要同时处理几件事：

- 商品页的参数很多，但不同品牌的写法不一样，很难直接横向比较；
- 评测和用户评价数量很大，真正和自己用途相关的内容却不多；
- 通用大模型能聊天，但价格、参数和库存经常说得像真的，实际没有数据依据；
- 比价工具能告诉你“哪里更便宜”，却回答不了“这款适不适合我”。

智购参谋把这些问题拆成一条可检查的流程：需求解析、候选筛选、规则评分、知识检索、解释生成。AI 负责理解和表达，商品事实和排序由本地数据和规则负责。

当前版本只覆盖笔记本电脑和手机。品类少是有意为之：这两个品类的参数可以横向比较，20 条商品也能逐条说明数据来源。与其铺开十几个品类、每个品类只放几条凑数，不如先把一条决策链路做完整。

## 2. 它怎么工作

```text
用户输入
   │
   ▼
需求解析 ──► 预算 / 品类 / 用途 / 核心需求 / 品牌偏好 / 硬性条件
   │
   ▼
候选筛选 ──► 预算内商品 + 超预算商品（单独列出）
   │
   ▼
匹配评分 ──► 预算、需求、性能、性价比、便携性等维度加权
   │
   ▼
推荐排序 ──► 按需求匹配度排序，不按价格或曝光排序
   │
   ├──► 知识检索：选购指南、FAQ、商品级资料
   ├──► AI 解释：只解释已有数据，不参与打分
   └──► 决策报告：评分构成、加减分项、数据来源、历史快照
```

有两个边界需要先说明：

1. **规则负责排序，模型不负责排序。** 同一件商品在不同需求下得分不同，但分数怎么算、权重是多少，都能在页面上展开查看。
2. **没有数据的维度不补默认分。** 缺参数时，该维度会被排除并注明原因，而不是当成 0 分或满分。

## 3. 同一预算，三种需求

这是项目最主要的演示方式。三轮都使用 2000 元预算，只改用途，排序会明显变化。以下数字来自当前 20 条商品数据和本地规则，不是写死的展示数据。

### 第一轮：拍照优先

输入：

```text
我想买一款 2000 元以内的手机，主要拍照，要拍得好看
```

| 排名 | 商品 | 参考价 | 匹配评分 |
|---:|---|---:|---:|
| 1 | 真我 GT Neo6 SE | 1899 元 | 81.6 |
| 2 | iQOO Z9 Turbo | 1799 元 | 51.5 |
| 3 | 红米 Turbo 4 | 1499 元 | 50.7 |

真我 GT Neo6 SE 的核心需求匹配得分为 100，预算匹配为 98.5。它的价格不是最低，但“拍照”这一项和用户需求对上了，所以排在前面。

### 第二轮：续航优先

输入：

```text
2000 元以内的手机，日常用，续航要长
```

| 排名 | 商品 | 参考价 | 匹配评分 |
|---:|---|---:|---:|
| 1 | iQOO Z9 Turbo | 1799 元 | 81.5 |
| 2 | 红米 Turbo 4 | 1499 元 | 80.7 |
| 3 | 真我 GT Neo6 SE | 1899 元 | 77.9 |

预算没有变，第一名换成了 iQOO Z9 Turbo。真我 GT Neo6 SE 仍然是一台适合拍照的手机，只是这次的需求是续航和日常使用。

### 第三轮：便携优先

输入：

```text
2000 元以内的手机，经常出差，要轻一点
```

| 排名 | 商品 | 参考价 | 匹配评分 |
|---:|---|---:|---:|
| 1 | 荣耀 X70 | 1599 元 | 62.2 |
| 2 | 真我 GT Neo6 SE | 1899 元 | 60.0 |
| 3 | iQOO Z9 Turbo | 1799 元 | 59.0 |

同一批商品，三种需求，三个不同的第一名。这里展示的不是“哪台手机最好”，而是“哪台手机更适合这次的需求”。

> 商品数据更新后，具体分数会变化。演示前请以应用内实时计算的结果为准，不要背上面的名次。

## 4. 已经实现的功能

| 页面 | 能做什么 | 说明 |
|---|---|---|
| 首页 | 用一段自然语言描述需求，直接进入分析 | 也支持在智能分析页用表单逐项填写 |
| 智能分析 | 需求解析、候选筛选、评分排序、报告导出 | 核心页面；含超预算商品、评分构成、AI 执行轨迹 |
| 商品比较 | 同品类 2–5 件商品横向对比 | 参数表、差异标记、优缺点、缺失数据提示 |
| AI 问答 | 知识库问答、具体商品推荐 | 有商品意图时结合商品库；知识库不足时用通用知识补答并标注 |
| 历史记录 | 查看历史分析、收藏商品 | 报告按快照保存；不同用户的数据相互隔离 |
| 商品维护（管理员） | 维护商品、分类、品牌、参数 | 支持新增、编辑、启用/停用 |
| 知识库管理（管理员） | 查看知识切片、重建索引、增删资料 | 可选向量检索；未配置时使用 BM25 |
| 全站概览（管理员） | 查看全部用户的分析记录 | 可删除记录；无归属的遗留记录单独标注 |
| 用户管理（管理员） | 改角色、重置密码、停用、删除账号 | 删除账号会级联删除其历史和收藏 |
| 个人设置 | AI 增强开关、价格取向、显示偏好 | 偏好按账号保存 |
| 关于 | 评分口径、数据来源和使用边界 | 不把演示数据说成实时数据 |

普通用户看不到管理页面。权限判断不只在界面上隐藏按钮，数据层写入口也会检查当前用户。

### AI 问答现在的行为

AI 问答不是单纯的聊天窗口，也不是只查知识库：

- 问选购原则（例如“笔记本多重适合带出门”）时，优先引用知识库资料；
- 问具体商品或预算（例如“2000 元以内手机推荐”）时，先从商品库检索真实候选，再让模型在候选范围内组织推荐，写清型号、参考价和匹配理由；
- 知识库和商品库都没有依据时，使用 AI 通用知识回答，并在界面上明确标注“未引用知识库”；
- 商品库价格是参考价，不是实时价格；系统匹配评分不是用户口碑或销量。

## 5. 技术实现

### 5.1 分层

```text
app.py                页面编排、登录入口、导航、异常兜底
src/ui/               Streamlit 界面；唯一依赖 Streamlit 的目录
src/                  业务逻辑；不依赖 Streamlit，可单独测试
  config.py           路径、环境变量、评分权重、标签
  demand_parser.py    自然语言 → Demand
  scoring.py          单商品多维度评分
  recommender.py      筛选、排序、超预算处理
  comparison.py       多商品比较
  report_service.py   报告组装与导出
  ai_service.py       模型调用（httpx，OpenAI 兼容接口）
  ai_enhance.py       提示词、结果校验、问答
  knowledge/          语料、切分、BM25、向量检索、知识管理
  agent/              只读工具注册表、编排循环、执行轨迹
  database.py         SQLite：账号、历史、收藏、偏好
storage/              运行时 SQLite 数据库
data/                 商品种子数据、知识文档、评测用例
tests/                自动化测试
docs/                 需求、架构、测试、演示和数据说明
```

`app.py` 只做编排，评分、筛选、比较等规则都在 `src/` 下。这样测试可以直接调用业务函数，不需要启动 Streamlit；以后如果换成 FastAPI，也可以先搬走业务层。

### 5.2 评分不是黑盒

总分的计算方式是：

```text
总分 = Σ（维度得分 × 该品类下的权重）
```

当前使用的维度包括预算匹配、核心需求匹配、性能功能适配、性价比和便携性。不同品类使用不同权重，权重集中配置在 `src/config.py`，并且有测试检查每个品类的权重和为 1。

几个具体规则：

- 预算内商品和超预算商品分开显示，超预算商品会写明超出多少；
- 同价位商品按需求匹配度排序，不按价格从低到高排；
- 缺失参数的维度不计分，页面注明“信息缺失”，不拿其他商品的值填充；
- 数据记录内部矛盾时标为“资料存疑”，但不因此把商品直接排除。

### 5.3 知识库：可选向量，保留离线回退

知识库有三类内容：

- 品类级：笔记本电脑、手机两份选购指南；
- 服务级：常见问题与术语说明；
- 商品级：由商品字段在建立索引时合成，不单独维护 20 份商品介绍。

检索支持两种模式：

- 配置了 Embedding 服务时，先走向量检索；
- 未配置、调用失败或没有足够相似的结果时，回退到中文二元组 + BM25 的关键词检索。

这样安排的原因是演示现场的网络和 API 不一定可靠。向量检索能提升语义匹配，但不能成为“没网就完全不能用”的单点。检索结果会经过阈值和相对截断，单次最多返回 3 条；没有可靠资料时不会硬编一个答案。

### 5.4 Agent 只做只读工具调用

AI 增强模式下，复杂问题会进入 Agent 编排。模型可以调用四个工具：

| 工具 | 用途 |
|---|---|
| `search_products` | 按预算、品类、用途筛选商品 |
| `get_product_detail` | 按商品 ID 读取完整信息 |
| `compare_products` | 比较同品类多件商品 |
| `search_knowledge` | 检索知识库 |

工具集里没有修改数据、写数据库、执行 SQL 或对外发请求的能力。每次工具调用都经过 pydantic 参数校验和业务语义校验；模型给错参数时直接拒绝并返回原因，不替它猜。编排最多 5 轮，失败或超时回到确定性管道，筛选、评分和报告仍然可用。

智能分析页可以展开“执行过程”，看到工具名、参数、结果摘要和状态。轨迹里记录的是真实调用，不是模型的思考过程。

### 5.5 抗幻觉

AI 可以写解释，但不参与商品数据和排序。当前实际校验分路径：

- 知识问答：检查价格和排他性结论，不通过就丢弃整条回答；
- 具体商品问答：检查回答里的价格是否来自商品库、检索资料或用户问题；商品名和推荐理由主要靠提示词约束，没有完整实体校验；
- 通用知识回答：不做事实校验，只在界面上标注“未引用知识库”；
- Agent 的工具参数经过两层校验，最终说明文本没有走完整的四类校验，页面提示“具体结论以工具返回数据为准”；
- AI 不参与评分、排序和历史报告的快照；
- 商品记录自相矛盾时标为“资料存疑”，提示用户核实，但不把数据问题算成商品缺点；
- 没有候选商品时，系统说明原因并给出放宽建议，不伪造结果。

这些检查不能保证模型永远不犯错，只是把已知的高风险内容挡在展示之前。

## 6. 数据说明

当前数据集：

| 品类 | 商品数 | 参考价格区间 | 品牌 |
|---|---:|---|---|
| 笔记本电脑 | 10 | 3519–11199 元 | 红米、荣耀、华为、联想、惠普、戴尔、华硕、苹果 |
| 手机 | 10 | 1499–5399 元 | 红米、荣耀、iQOO、真我、OPPO、小米、vivo、华为、苹果 |

- 品牌与型号真实存在，能在网上搜到；
- 价格是按公开资料整理的参考价，**不是实时价格**，会随促销变化；
- 参数经过简化，部分档位（如处理器档位、拍照档位）是为规则评分设定的 1–5 级，不是厂商跑分；
- 20 条商品都有 `source_url`，但 `data_status` 全部为 `unverified`，即没有逐条核验；
- 图片是外链，加载失败时回落到品类图标；
- 数据集不包含销量、用户评价、库存、保修和售后信息。

详细口径见 [docs/data-disclaimer.md](docs/data-disclaimer.md)。

```bash

```

当前收集到 **1037 条测试，分布在 34 个测试文件中**。测试不需要网络，也不需要 API 密钥。

覆盖范围包括：需求解析、预算边界、筛选排序、评分权重、商品比较、SQLite 读写、按用户隔离、权限边界、知识检索、Agent 工具校验、AI 失败降级、Streamlit 页面渲染和端到端验收。

### 效果评测

评测集在 `data/evaluation/cases.json`，共 41 条用例，覆盖需求理解、预算边界、不支持的品类、知识检索、语料外反例、多商品比较、幻觉场景和工具调用。

当前自动指标：

| 指标 | 结果 |
|---|---:|
| 需求理解准确率 | 25/25 |
| 硬性条件满足率 | 9/9 |
| 检索质量 | 17/17 |
| 幻觉场景通过率 | 6/6 |
| 推荐相关性 | 9/9 |

这些数字来自项目自己构造并标注的评测集，不是第三方基准。它的用途是检查“在明确口径下有没有退步”，不能读成“系统整体准确率 100%”。任务完成率和证据支持率仍需要人工复核，报告里单独列出。

## 8. 本地运行

环境要求：Python 3.10 或更高版本。

```bash
pip install -r requirements.txt
streamlit run app.py
```

打开 <http://localhost:8501>。不配置模型密钥也能使用智能分析、商品比较、历史记录等核心功能；AI 问答需要配置模型密钥。

环境变量可以复制 `.env.example` 为 `.env` 后填写：

```bash
copy .env.example .env
```

主要配置：

| 变量 | 用途 |
|---|---|
| `ZHIGOU_LLM_API_KEY` | 对话模型密钥；留空时 AI 功能不可用，本地规则功能正常 |
| `ZHIGOU_LLM_BASE_URL` | OpenAI 兼容接口地址 |
| `ZHIGOU_LLM_MODEL` | 模型名 |
| `ZHIGOU_EMBEDDING_API_KEY` | 可选的向量检索密钥；留空时使用 BM25 |
| `ZHIGOU_ADMIN_USERNAME` / `ZHIGOU_ADMIN_PASSWORD` | 首次启动时创建管理员 |
| `ZHIGOU_ALLOW_REGISTRATION` | 是否开放注册 |

密钥只从环境变量或 Streamlit Secrets 读取，不写进源码。详细部署方式见 [DEPLOY.md](DEPLOY.md)。

### 已知限制

- 只有 20 件商品、2 个品类，不能覆盖真实购物平台的长尾需求；
- 不接入电商平台，不提供实时价格、库存、销量或真实评价；
- Streamlit Community Cloud 的文件系统是临时的，应用休眠或重新部署后，账号、历史和收藏可能重置；
- 账号体系是演示级鉴权：没有登录限流、没有会话过期，公开演示不要输入真实个人信息；
- 当前是 Streamlit 单体，没有 HTTP API，SQLite 也不适合多实例并发写；
- 评测集是自评，样本量有限，不能替代真实的用户研究。

下一步计划见 [docs/roadmap.md](docs/roadmap.md)。

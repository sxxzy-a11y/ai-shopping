# 项目说明：智购参谋

## 项目简介

智购参谋把用户的一句自然语言购物需求，变成一份有预算约束、有评分依据、有数据来源的购买建议。

## 基本信息

| 项 | 内容 |
|---|---|
| 项目名称 | 智购参谋 |
| 项目形态 | Web 应用（Streamlit + SQLite） |
| 面向场景 | 笔记本电脑、手机的选购决策 |
| 在线演示 | <https://ai-shopping-muofh8jcwgc3weydpvmagc.streamlit.app/> |
| 代码仓库 | <https://github.com/sxxzy-a11y/ai-shopping> |
| 核心能力 | 需求解析、商品筛选、匹配评分、多商品比较、知识问答、受控 Agent |
| 当前数据 | 20 件商品、2 个品类、13 个品牌 |

## 问题

消费者在买 3C 产品时，通常不是没有信息，而是信息太多、口径不一。

商品页强调卖点，评测强调极限性能，用户评价又带有很强的个人偏好。用户真正需要回答的是：在我的预算和用途下，哪一件更合适？现有工具各有缺口：

- 电商搜索和推荐以转化为目标，排序不透明；
- 比价工具能比较价格，但不理解用途和偏好；
- 通用大模型能理解需求，却容易编造价格、参数和评价；
- 参数表能罗列规格，但不会替用户做取舍。

## 方案

系统把一次购买决策拆成五步：

```text
自然语言输入
  → 结构化需求（预算、品类、用途、偏好、硬性条件）
  → 候选筛选（预算内 / 超预算分开）
  → 多维度匹配评分（规则计算）
  → 知识检索与解释（RAG + 可选 Agent）
  → 决策报告与历史快照
```

其中，商品事实来自本地 SQLite，排序由确定性规则完成，AI 只负责理解表达和解释结果。这样既能处理口语化输入，又不会让模型凭空决定价格或名次。

## 三个可以现场验证的点

### 1. 同一预算，换一个用途，排序会变

用 2000 元预算分别输入“主要拍照”“续航要长”“经常出差，要轻一点”：

| 需求 | 第一名 | 参考价 | 匹配评分 |
|---|---|---:|---:|
| 拍照优先 | 真我 GT Neo6 SE | 1899 元 | 81.6 |
| 续航优先 | iQOO Z9 Turbo | 1799 元 | 81.5 |
| 便携优先 | 荣耀 X70 | 1599 元 | 62.2 |

预算没有变，第一名换了三次。这说明系统排序看的是需求匹配，不是固定榜单。

### 2. 每条推荐都能拆开看

点开任意商品，可以看到各维度得分、权重、加分项和扣分项。例如真我 GT Neo6 SE 在拍照场景中：

- 预算匹配 98.5，权重 0.25；
- 核心需求匹配 100，权重 0.30；
- 性能功能适配 62.5，权重 0.25；
- 性价比 58，权重 0.10；
- 便携性 55.7，权重 0.10。

总分 81.6 不是模型“感觉”出来的，而是这几个数加权得到的。

### 3. AI 与商品事实分开

AI 生成内容按用途走不同检查。知识问答检查价格和排他性结论；具体商品问答检查价格是否来自商品库、资料或用户问题；独立推荐解释函数还会检查参数数值和存疑属性。出现数据里没有的价格或没有依据的“销量第一”时，这段 AI 文字会被丢弃，规则结果仍然保留。具体商品问答的商品名主要靠提示词约束，Agent 的最终说明也没有走完整的四类事实校验，页面会提示以工具返回数据为准。AI 不参与评分，也不写入历史报告的快照。

## 技术组成

| 模块 | 做法 |
|---|---|
| 需求解析 | 本地规则 + 可选模型解析，统一输出 `Demand` |
| 商品数据 | SQLite；20 条商品，字段含来源、价格、参数、优缺点 |
| 推荐排序 | 按品类配置权重，预算/需求/性能/性价比/便携性加权 |
| 知识库 | 2 份品类指南 + 1 份 FAQ + 商品级条目；向量检索，失败回退 BM25 |
| AI 问答 | 知识库优先；具体商品问题结合商品库；无依据时用通用知识并标注 |
| Agent | 4 个只读工具，最多 5 轮，记录真实工具调用轨迹 |
| 历史记录 | 报告 JSON 快照，商品数据更新后不改写旧结论 |
| 权限 | 普通用户 / 管理员；数据按用户隔离；写入口校验 |

## 工程与验证

- 1037 条自动化测试，34 个测试文件，不依赖网络和 API 密钥；
- 41 条效果评测用例，覆盖需求理解、预算边界、知识检索、语料外问题、比较和幻觉场景；
- 当前自动指标全部通过，但评测集由项目自行构造，属于自评，不是第三方基准；
- 任务完成率和证据支持率尚未做人工测量，报告中单独列明；
- 所有商品记录标注为“未核验”，价格是参考价，不冒充实时数据。

## 项目价值

对消费者，智购参谋把“参数比较”变成“需求匹配”，并把推荐理由摊开，减少被单一卖点或价格带偏的情况。

对 AI 应用开发，它提供了一个可复用的工程思路：让模型做它擅长的事（理解、表达、工具选择），把事实和排序留在可测试的代码里；模型失败时，基础功能仍然可用。

当前版本适合作为 3C 选购的演示和教学项目。若要用于真实交易场景，还需要接入授权商品数据、补上实时价格与库存、把演示级鉴权换成生产级方案，并扩大评测样本。

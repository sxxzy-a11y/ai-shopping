# 效果评测报告

评测集：`data/evaluation/cases.json`，版本 2.0，共 41 条用例，更新于 2026-10-15。

这是一次自评。用例由项目自己构造和标注，每条用例的构造依据写在 `origin` 字段里。下面的数字只在本文说明的口径下成立，不是第三方基准，也不是真实用户调查。

## 评测方法

- 只调用公开入口，不读取被测函数的中间结果；
- 自动能算的指标单列，需要人读的指标不折进总分；
- 没有执行的检查写“尚未测量”，不填目标值；
- 评测集用于回归，避免改动让已有能力退步。

运行方式：

```bash
python scripts/evaluate.py
python scripts/evaluate.py --only 知识检索
```

## 自动指标

| 指标 | 计算口径 | 结果 |
|---|---|---:|
| 需求理解准确率 | 标注字段逐项比对 | 25/25 |
| 硬性条件满足率 | 设置预算的用例中，推荐商品全部在预算内的比例 | 9/9 |
| 检索质量 | 知识检索用例的命中类型和反例检查 | 17/17 |
| 幻觉场景通过率 | 六类可判定幻觉场景中，行为符合预期的比例 | 6/6 |
| 推荐相关性 | 与实际结果和人工标注的必含 / 必排集合比对 | 9/9 |

## 人工指标

| 指标 | 状态 |
|---|---|
| 任务完成率 | 尚未测量，需要观察用户能否独立完成选购任务 |
| 证据支持率 | 尚未测量，需要人工判断推荐理由中的事实是否有资料支持 |

这两项没有实测值。把它们折算进一个“综合得分”会让读者误以为那是测量结果，所以单独列出。

## 失败项

本次运行没有失败项。

评测集在建设过程中发现过缺陷，修复后重跑才全部通过。这说明评测确实在起作用，但也意味着当前结果不是一次独立的“盲测”。

## 怎么读这组数字

**不要读成“系统准确率 100%”。**

更准确的说法是：

- 在这 41 条自建用例上，当前实现的行为符合预期；
- 需求理解、预算边界、检索和幻觉场景的回归基线没有退步；
- 任务完成率、证据支持率和真实用户满意度仍未测量；
- 用例数量有限，不能覆盖真实购物平台的长尾需求。

如果要证明系统在真实场景有效，需要新增用户研究、扩大标注样本，并让不参与开发的人参与标注和复核。

# 账号与鉴权边界

## 定位

智购参谋的账号系统用于演示两种角色和数据隔离，不是生产级鉴权。

它能做到：

- 用户名 + 密码登录；
- 普通用户和管理员两种角色；
- 历史、收藏、偏好按用户隔离；
- 管理员维护商品、知识库和用户；
- 未登录时不加载商品数据；
- 账号被停用或删除后，下一次交互时失效。

它做不到：

- 登录限流和失败次数限制；
- 会话过期；
- 找回密码和邮箱验证；
- CSRF 防护；
- 多租户、组织和细粒度权限。

## 当前公网演示

比赛演示部署在 Streamlit Community Cloud，允许公开访问。当前代码默认开放注册；如果部署时把 `ZHIGOU_ALLOW_REGISTRATION` 设为 `false`，登录页不会显示注册入口。

公开演示只用于体验，不应输入真实个人信息、真实密码或其他敏感数据。Cloud 文件系统是临时的，应用休眠或重新部署后，账号、历史、收藏可能重置。

这不是“安全的公共服务”，只是让评委和观众能看到完整流程的演示环境。若要用于真实业务，至少需要补上：

- 登录限流、会话管理和过期策略；
- 密码找回、邮箱或手机号验证；
- CSRF 防护和安全响应头；
- 生产级数据库、备份和审计；
- 在应用前增加一层访问控制，管理端不直接暴露公网。

## 登录态

登录态只保存在 Streamlit 的 `session_state` 中，不写 Cookie，不放进 URL。

代价是刷新页面需要重新登录。这样做的好处是凭据不会被复制到浏览器历史、代理日志或可分享的地址里。Streamlit 没有稳定的官方 Cookie API，引入第三方组件会让部署和测试多一层不确定性，因此当前选择接受这个限制。

## 密码存储

- 使用 Python 标准库 `hashlib.pbkdf2_hmac`；
- 随机 16 字节盐；
- 存储格式为 `pbkdf2_sha256$<迭代次数>$<盐>$<哈希>`；
- 迭代次数写在凭据串里，校验时从串里读，调整参数不会让旧密码失效；
- 数据库不存明文密码；
- 用户名不存在、密码错误、账号停用返回相同提示，避免枚举用户名。

当前迭代次数为 60 万。它在开发机上大约需要几十毫秒到一百毫秒，慢是刻意的。

## 数据最小化

账号表只保存用户名、角色、状态、密码凭据和创建时间。没有邮箱、手机号、姓名、设备标识或地理位置。

分析记录只保存内部账号标识，用于按用户隔离。单用户时期留下的无归属记录只对管理员可见，系统没有把它们分配给任何账号。

## 角色与删除

普通用户只能看到自己的历史、收藏和偏好。管理员可以查看全站记录、维护商品和知识库、调整用户角色。

删除账号会级联删除其历史、收藏和偏好，确认前会显示影响条数。不能删除自己，也不能删除最后一个可用管理员。停用比删除更适合临时封禁，因为停用可逆。

## 管理员密码重置

首次启动时，如果账号表为空，系统会创建初始管理员。账号和密码取自 `ZHIGOU_ADMIN_USERNAME` / `ZHIGOU_ADMIN_PASSWORD`；没有配置时生成随机密码，只在启动终端打印一次。

如果部署后忘记管理员密码，可以在 Streamlit Secrets 临时设置：

```toml
ZHIGOU_RESET_ADMIN_PASSWORD = "新的强密码"
```

重启后，启动流程会把已存在的管理员账号密码覆盖为新值。登录成功后应立即删除 `ZHIGOU_RESET_ADMIN_PASSWORD` 并再次重启。

`ZHIGOU_ADMIN_PASSWORD` 只用于账号表为空时创建初始管理员，不会修改已有管理员的密码。新部署可以同时配置它；已有部署只用 `ZHIGOU_RESET_ADMIN_PASSWORD` 重置。

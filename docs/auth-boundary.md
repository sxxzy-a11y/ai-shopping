# 鉴权边界说明

> **一句话**：本系统的账号体系是**演示级鉴权**，用于展示「不同角色看到不同的东西」
> 与「数据按用户隔离」。**它不是生产级方案，不该对外提供任何真实服务。**

这份文档存在的意义是把「它**不能**做什么」写清楚。只写「仅供演示」四个字
等于什么都没说——使用者会按自己的经验去猜它能扛多少，而猜错的代价可能是
把别人的数据露出去。

界面上同一份说明出现在两个地方：**登录页**与**项目说明页**。
文案的唯一来源是 `src/ui/disclosure.py`，两处共用——
这是**披露限制**的内容，两处措辞一旦漂移，读者会以为自己看到的是完整清单。

---

## 1. 它能做什么

| 能力 | 说明 |
|---|---|
| 登录与登出 | 用户名 + 密码，密码用标准库 `pbkdf2_hmac` 加盐派生存库 |
| 自助注册 | 任何访问者都能注册；**注册得到的账号一律是普通用户** |
| 两种角色 | 管理员 / 普通用户。角色决定侧边栏可见的页面与可执行的操作 |
| 数据按用户隔离 | 历史记录、收藏、个人偏好都归属到具体账号，互相看不到 |
| 管理员维护数据 | 用户管理、全站概览、商品与分类品牌维护 |

## 2. 它**不能**做什么

- **没有会话过期机制**：登录状态一直有效，直到主动登出或关闭页面
- **没有登录限流**：连续尝试密码不会被拦住，没有失败次数限制
- **没有找回密码**：忘了密码只能由管理员重置
- **没有 CSRF 防护**
- **刷新浏览器页面后需要重新登录**：凭据只存在 `st.session_state` 里，
  不写 Cookie、不放进 URL——代价是刷新即掉登录，好处是凭据无法被复制分享
- **没有邮箱验证、二次验证**
- **不做多租户 / 组织 / 细粒度授权**：只有两种角色

### 为什么刷新就要重新登录

Streamlit 没有官方的 Cookie API。要「刷新不掉登录」只有两条路：引第三方组件
（违反项目的零新增依赖），或者把令牌放进 URL 查询参数——后者会让凭据出现在
浏览器历史、代理日志和用户能随手复制粘贴的地址栏里。**用可分享的凭据换一点
便利，方向反了。** 所以选择刷新后重新登录，并把这件事如实写进说明。

## 3. 所以，部署要求

> ⚠️ **演示时只绑定本机地址，不要把这个服务暴露到公网。**

注册是开放的：任何能访问到这个地址的人都能创建账号并进入。加上没有限流、
没有会话过期，把它放到公网上等于敞开。README 的「快速开始」一节也写了这一条。

## 4. 密码是怎么存的

- 标准库 `hashlib.pbkdf2_hmac`，随机 16 字节盐，**不引入任何新依赖**
- 存储格式 `pbkdf2_sha256$<迭代次数>$<盐>$<哈希>`，**算法与参数写在串里**
- 校验时**从串里读迭代次数**，不读代码里的常量——所以日后调参数不会让
  已有密码失效
- 迭代 60 万次（实测本机约 93 毫秒）。慢是刻意的：这正是它起作用的方式
- 写入口**只收明文、内部派生**，所以数据库里不可能出现明文密码
- 「用户名不存在」与「密码错误」返回**完全相同**的中文提示；
  「账号已停用」也一样。能分开说，就等于给了一个枚举有效用户名的地方

## 5. 数据最小化

账号表只有：用户名、角色、状态、密码凭据、创建时间。
**没有邮箱、手机号、姓名、设备标识或地理位置**——本应用不需要它们，
收了也只是白拿用户信息。

分析记录里保存的归属只有**本应用内部的账号标识**（一个用户名）。
规格里原本写着「记录字段不包含用户身份信息」，按用户隔离历史必然要在记录里
存归属，所以那条需求被显式改写成「只存内部账号标识，仍不采集设备标识、
地理位置等额外信息」。

单用户时期留下的记录与收藏**标为无归属**，只对管理员可见。
系统没有把它们划给任何账号——那样等于编造归属。
